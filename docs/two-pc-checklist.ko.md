# 두 PC 실사용 점검 — 관리자용 / 사용자용 0.8.0

이 체크리스트를 완료하기 전에는 다른 PC에서의 설치·LLM 대화까지 검증 완료로 취급하지 않습니다. 실제 봇 토큰·비밀번호는 결과 보고에 넣지 마세요.

## 1. 서버 PC (관리자)

1. `Hermes-Admin-Setup-0.8.0.zip`과 전달된 `SHA256SUMS.txt`를 대조합니다. `Get-FileHash <ZIP 경로> -Algorithm SHA256`으로 확인할 수 있습니다. 해시는 코드 서명을 대신하지 않습니다.
2. 압축을 모두 풀고 `Start-HermesAdminSetup.cmd`를 실행합니다. Docker Desktop의 Linux 엔진과 NetBird를 켭니다.
3. 서버·관리자·팀·채널을 설정하고 Bot Control 설치를 선택합니다. 다른 PC 접속을 위해 공개 범위를 **NetBird로 공유**로 선택합니다. 기존 8065 서버와 다른 포트를 사용합니다.
4. 완료 후 서버 주소가 `127.0.0.1`이 아닌 **서버 PC의 NetBird 주소**인지 확인합니다. 시스템 관리자 계정으로 직접 로그인합니다.
5. 아래 봇 발급 영역에서 사용자별로 서로 다른 봇을 만듭니다. 완료 화면에서 서버 URL·봇 사용자 이름·Home Channel ID를 확인합니다. 토큰은 복사 버튼으로 필요한 사용자에게 안전하게 전달합니다. 사람 계정 암호나 관리자 세션 토큰은 전달하지 않습니다.
6. 사용자의 사람 계정은 별도입니다. 관리 콘솔의 사용자 관리/팀 초대에서 해당 서버의 사용자 계정·팀 접근을 준비합니다. 메일 미설정 환경에서는 초대 메일 발송에 의존하지 말고 승인된 초대 링크 또는 관리자의 계정 생성 절차를 이용합니다. 봇 토큰으로 Desktop에 로그인하지 않습니다.

## 2. 사용자 PC (연구원)

1. Windows 10/11 x64, Git for Windows, NetBird 연결을 준비합니다. 관리자와 동일한 NetBird 네트워크에 연결되어 있어야 합니다.
2. 먼저 브라우저에서 전달받은 **서버 URL**을 엽니다. 실패하면 설치를 시작하지 말고 서버의 공유 상태·NetBird 정책·Windows 방화벽을 관리자와 확인합니다.
3. `Hermes-User-Setup-0.8.0.zip`을 풀고 `Start-HermesEasySetup.cmd`를 실행합니다. 관리자 패키지를 실행해 사용자 PC에 새 서버를 만들지 않습니다.
4. PC 확인 → 계획·승인 → Hermes 설치·검증 → Mattermost Desktop 설치/서버 등록 → Codex 인증·모델 → 연구실 연결 순서입니다. OAuth는 본인의 계정으로 직접 승인합니다.
5. Desktop에서 **그 서버의 사람 계정**으로 로그인합니다. 다른 Mattermost 서버 계정은 자동으로 공유되지 않습니다.
6. 연구실 연결에서 새 프로필, Full name·역할, 서버 URL, 받은 봇 토큰, Home Channel ID를 입력합니다. **NetBird IP는 사용자 PC 자신의 주소**입니다. Dashboard 포트 기본값은 9119입니다.
7. Dashboard 기본 인증 `admin / 12345678`은 공개 초기값입니다. 변경 가능하며 실사용에는 고유한 암호 또는 적절한 NetBird 접근 정책이 필요합니다. 마법사는 이 정책을 대신 변경하지 않습니다.
8. 봇 토큰·채널 검증이 통과한 뒤 부팅 작업 등록의 Windows 관리자 승인을 진행합니다. 등록 실패 시 같은 프로필을 이어서 설정하며 기존 WSL/다른 프로필을 삭제하지 않습니다.

## 3. 왕복 연결과 실제 응답 확인

두 방향이 모두 필요합니다.

| 방향 | 주소 | 확인할 것 |
|---|---|---|
| 사용자 PC → 서버 PC | `http://<서버-NetBird-IP>:<Mattermost-포트>` | Desktop 로그인, 봇 토큰·채널 검사 |
| 서버의 Mattermost → 사용자 PC | `http://<사용자-NetBird-IP>:9119` | 인증된 Dashboard 등록, Bot Control 적용 |

1. 관리자는 Bot Control에서 등록된 봇·프로필·사용자 PC Dashboard 주소를 확인합니다.
2. 이름/역할과 `멘션된 경우만`, `대화 위치 유지`를 적용합니다. 적용은 해당 프로필의 활성 Mattermost 세션을 정리하고 게이트웨이 재시작을 요청하므로 진행 중인 작업이 없는 때 실시합니다.
3. 일반 채널에서 `@봇사용자이름 안녕` → 일반 메시지로 응답하는지 확인합니다.
4. 기존 스레드 안에서 `@봇사용자이름 이 스레드에서 답해줘` → 해당 스레드에 응답하는지 확인합니다.
5. 멘션 없는 일반 채널 메시지 → 응답하지 않는지 확인합니다. DM/특수 메시지의 동작은 별도이며 일반 채널 조건과 같다고 가정하지 않습니다.
6. 일반 사람 계정과 봇이 Bot Control 관리 화면/관리 API를 사용하지 못하는지 확인합니다.
7. 마법사·터미널을 닫은 뒤에도 Gateway·Dashboard가 작동하는지 확인하고, 가능하면 사용자 PC 재시작 후 다시 확인합니다. 서버는 Docker Desktop이 실행되어 있어야 합니다.

## 결과 기록 (비밀 제외)

- 사용한 두 ZIP의 버전/해시, Windows 버전
- 서버 URL 접속: 성공/실패
- 사용자 마법사 완료: 성공/실패 단계
- Bot Control 등록 및 적용: 성공/실패
- 일반 메시지/스레드/무멘션 응답: 각각 성공/실패
- 창 종료 후/재부팅 후 자동 시작: 성공/미검증/실패
- 토큰·비밀번호를 제외한 오류 문구

같은 PC의 Docker 통합 검증은 완료했지만, Dashboard 계약 검사에서는 실제 개인 에이전트 대신 인증된 테스트 모형을 사용했습니다. 위 항목이 실제 Hermes·LLM과 다른 PC에서의 최종 확인입니다.
