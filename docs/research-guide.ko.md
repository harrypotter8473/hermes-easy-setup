# 내 Windows PC에 만드는 1인 연구실 — 초기 버전

`Start-HermesResearchSetup.cmd`를 실행합니다. 기존 사용자용·관리자용 마법사는 그대로 유지됩니다. 이 초기 버전은 같은 PC에 Mattermost 서버와 Hermes 독립 프로필 4개를 구성하는 통합 흐름입니다. 자동 토론·연구 진행은 아직 포함하지 않습니다.

## 준비물

- 지원되는 Windows 10/11 x64, Git for Windows, Docker Desktop의 Linux 엔진
- Mattermost 관리자용 이메일과 새 비밀번호
- 모델 로그인에 사용할 ChatGPT/Codex 계정과 인터넷 연결

Docker Desktop이 없으면 마법사에서 공식 설치 파일을 다운로드·검증하고 사용자 동의 후 설치할 수 있습니다. Git 자체는 별도로 준비해야 합니다. Mattermost Desktop·NetBird·개별 Hermes Dashboard는 이 로컬 초기 버전에서 필요하지 않습니다.

## 1. 로컬 서버

1. 창을 열면 Docker 준비 상태를 조회합니다. 시스템 전체 설치와 사용자별 설치를 확인하고, CLI·앱·Compose의 공식 서명과 로컬 Linux 엔진을 검사합니다. PATH에서 명령을 못 찾았다는 이유만으로 재설치하지 않습니다.
2. 미설치이고 PC 조건을 충족하면 다운로드·설치 동의 후 `공식 Docker 다운로드·설치`를 누릅니다. 고정된 공식 설치 파일의 SHA-256과 Docker 배포자 서명을 확인한 뒤 설치합니다. 이미 설치된 Docker의 업데이트·제거·재설치는 수행하지 않습니다.
3. Docker Desktop을 열어 약관·초기 설정을 직접 확인합니다. WSL2·가상화·Windows 기능·권한 문제가 있다면 표시되는 안내를 따릅니다. Windows 기능을 자동으로 켜거나 조직 정책을 우회하지 않습니다. 재부팅이 필요하면 직접 재부팅하고 다시 마법사를 실행하세요.
4. `Docker 준비 다시 확인`으로 Linux 엔진과 Compose를 확인합니다. 설치 성공만으로 서버 준비 완료를 표시하지 않습니다.
5. 서버 ID·포트·관리자 이름·이메일·비밀번호를 입력하고 생성 동의 후 `로컬 서버 설치`를 누릅니다.
6. 새 Mattermost·PostgreSQL 컨테이너와 연구용 팀·채널을 만듭니다. 기본 주소는 `http://127.0.0.1:18065`입니다.
7. `내 연구실 열기`에서 만든 관리자 계정으로 로그인합니다. 서버는 이 PC에서만 열리며 외부 공개를 하지 않습니다.

이 마법사가 만든 서버는 같은 ID로 불러오거나 이어서 설치할 수 있습니다. 기존 다른 서버·컨테이너·프로필은 제거하지 않습니다.

### Docker를 사용할 수 없다면

화면에서 PC 조건과 대안을 안내합니다. WSL2가 허용되면 Ubuntu 내부에 Mattermost·PostgreSQL을 직접 설치하는 경로를 별도로 개발할 수 있습니다. WSL2 역시 가상화가 필요합니다. 가상화도 사용할 수 없다면 별도 Linux 서버 또는 기존 Mattermost 서버를 사용하는 구성이 대안이며, 이 경우 같은 Windows PC 한 대에서 서버까지 운영한다는 조건은 변경됩니다. 이 마법사는 아직 이러한 대안의 자동 설치·연결을 제공하지 않습니다. 조직 정책으로 Docker가 금지되면 승인된 환경을 사용하세요.

Docker 설치 파일은 동봉하지 않고 실제 동의·실행 시 다운로드합니다. 현재 고정 버전·공식 URL·체크섬은 `config/docker-desktop.json`에서 확인할 수 있습니다. 설치 파일과 서명 검증이 실패하면 실행하지 않습니다. 고정 파일이 더 이상 제공되지 않으면 임의의 다른 버전을 자동 실행하지 않고 공식 설치 안내를 확인하도록 중단합니다. [Docker 공식 설치·약관](https://docs.docker.com/desktop/setup/install/windows-install/), [공식 릴리스·체크섬](https://docs.docker.com/desktop/release-notes/)

## 2. Hermes·모델

`PC 확인·설치 계획`으로 경로와 고정 릴리스를 검토하고 동의 후 설치합니다. 이미 마법사로 설치한 Hermes가 있다면 `기존 Hermes·인증 확인`을 사용할 수 있습니다. 모델 계정 로그인은 인증 페이지에서 직접 진행하며, 계정에서 사용할 모델을 선택합니다. 실제 설치 무결성·로그인·모델은 연구팀 연결 전에 다시 확인합니다.

## 3. 네 에이전트 — 한 페이지에서 설정

네 행의 이름·봇 토큰·역할을 입력합니다. `봇 발급용 관리자 비밀번호`를 넣고 각 행의 `봇 발급`을 누르면 같은 연구실에 일반 봇을 만들고 토큰을 해당 행에 채웁니다. 기존 일반 봇 토큰을 직접 입력해도 됩니다. 서로 다른 활성 봇 4개 모두 연구 채널의 멤버여야 합니다.

임시 역할은 총괄·조사·실행·검토이며 네 역할을 하나씩 선택합니다. 역할 이름과 지침은 펼침 영역에서 수정·저장할 수 있습니다. 역할은 행동 지침이지 별도 운영체제 권한이나 감사 강제 장치가 아닙니다.

동의 후 `연구팀 생성·연결`을 누르면 각각 별도의 SOUL·메모리·세션·Mattermost 토큰을 가진 프로필을 구성합니다. 공통 모델 계정 인증은 Hermes의 정상 동작대로 공유합니다. 고정 프로필 및 Mattermost 봇 사용자 이름은 다음과 같습니다.

| 프로필 / 봇 사용자 이름 | 처음 표시하는 이름·역할 |
|---|---|
| `research-lead` | 총괄 |
| `research-scout` | 조사 |
| `research-worker` | 실행 |
| `research-reviewer` | 검토 |

표시 이름과 역할은 바꿀 수 있습니다. 기존 발급 봇을 다시 불러올 때는 발급 당시 봇 표시 이름을 사용하세요. 이후 Hermes 표시 이름 변경은 기존 Mattermost 계정의 이름을 자동 변경하지 않습니다.

## 나중에 변경 / 실패 후 재시도

서버를 불러오면 저장된 네 이름·역할·모델을 복원합니다. 토큰은 평문 상태 파일에서 자동 불러오지 않습니다. 같은 봇 발급 버튼으로 암호화 보관된 토큰을 채우거나 직접 입력하세요. 역할 템플릿 저장만으로 실행 중인 에이전트가 바뀌지는 않습니다. `이 마법사에서 만든 연구 프로필을 재설정`을 선택하고 다시 연결해야 적용됩니다. 메모리와 세션은 유지됩니다.

프로필별 성공·실패를 표시하고 성공한 구성은 보존합니다. 기존 프로필의 재사용은 이 마법사의 소유 기록과 봇 ID가 일치할 때만 허용합니다. 다른 봇 계정으로 교체하거나 소유 기록이 없는 부분 생성 폴더를 자동 인수하지는 않습니다. 토큰 교체는 같은 봇 계정에 새로 발급된 토큰으로 가능합니다.

## 완료 확인과 운영 범위

Gateway PID와 현재 사용자 예약 작업 실행 상태를 확인한 뒤 완료로 표시합니다. Mattermost 연구 채널에서 `@research-lead`, `@research-scout`, `@research-worker`, `@research-reviewer`를 각각 멘션해 실제 모델 답변을 확인하세요. 이 답변까지 확인해야 전체 연결을 검증한 것입니다.

Gateway는 Windows 로그인 시 현재 사용자 권한으로 시작합니다. Docker Desktop이 실행 중이어야 서버가 열립니다. 로그인 전 부팅 서비스·무중단 운영·자동 백업·자동 연구 협업·외부 접속은 이 초기 버전의 제공 범위가 아닙니다.

설치 런타임의 `research/roles.json`에는 역할 템플릿, `research/team.json`에는 공개 팀 구성·소유·성공 상태가 저장됩니다. 입력 전송과 발급 토큰 보관은 Windows DPAPI를 사용하지만 Hermes 실행용 프로필 `.env`에는 토큰이 평문으로 존재합니다. `.env`·인증 파일·토큰·전체 로그를 Git이나 공개 이슈에 올리지 마세요.

소스와 모킹·화면·배포 테스트를 제공하는 미서명 초기 버전입니다. 실제 Docker 설치와 모델 답변까지의 종단간 검증은 사용자 환경에서 별도로 진행해야 합니다. GitHub에 자동 게시되지 않습니다.
