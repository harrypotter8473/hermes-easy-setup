# 내 Windows PC에 만드는 1인 연구실 — 초기 버전

`Start-HermesResearchSetup.cmd`를 실행합니다. 기존 사용자용·관리자용 마법사와 서버 설치 흐름은 유지됩니다. 네 역할의 전체 페르소나와 권한·감사 중개 실행기를 구성합니다. 미정 운영 설정을 채우기 전에는 연구 실행을 보류합니다.

## 준비물

- 지원되는 Windows 10/11 x64, Git for Windows, Docker Desktop의 Linux 엔진
- Mattermost 관리자용 이메일과 새 비밀번호
- 모델 로그인에 사용할 ChatGPT/Codex 계정과 인터넷 연결

Docker Desktop이 없으면 마법사에서 공식 설치 파일을 다운로드·검증하고 사용자 동의 후 설치할 수 있습니다. Git 자체는 별도로 준비해야 합니다. Mattermost Desktop·NetBird·개별 Hermes Dashboard는 이 로컬 초기 버전에서 필요하지 않습니다.

## 1. 로컬 서버

1. 창을 열면 Docker 준비 상태를 조회합니다. 시스템 전체 설치와 사용자별 설치를 확인하고, CLI·앱·Compose의 공식 서명과 로컬 Linux 엔진을 검사합니다. PATH에서 명령을 못 찾았다는 이유만으로 재설치하지 않습니다.
2. 미설치이고 PC 조건을 충족하면 다운로드·설치 동의 후 `공식 Docker 다운로드·설치`를 누릅니다. 고정된 공식 설치 파일의 SHA-256과 Docker 배포자 서명을 확인한 뒤 설치합니다. 이미 설치된 Docker의 업데이트·제거·재설치는 수행하지 않습니다.
3. Docker Desktop을 열어 약관·초기 설정을 직접 확인합니다. WSL2·가상화·Windows 기능·권한 문제가 있다면 표시되는 안내를 따릅니다. Windows 기능을 자동으로 켜거나 조직 정책을 우회하지 않습니다. 재부팅이 필요하면 직접 재부팅하고 다시 마법사를 실행하세요.
4. `Docker 준비 다시 확인`으로 Linux 엔진과 Compose를 확인합니다. 설치 성공만으로 서버 준비 완료를 표시하지 않습니다.
5. 서버 ID·포트·관리자 이름·이메일·비밀번호를 입력하고 생성 동의 후 `로컬 서버 설치`를 누릅니다.
6. 새 Mattermost·PostgreSQL 컨테이너와 연구용 팀·채널을 만듭니다. 기본 주소는 `http://127.0.0.1:18065`입니다.
7. `내 연구실 열기`에서 만든 관리자 계정으로 로그인합니다. 서버는 이 PC에서만 열리며 외부 공개를 하지 않습니다.

이 마법사가 만든 서버는 같은 ID로 불러오거나 이어서 설치할 수 있습니다. 기존 다른 서버·컨테이너·프로필은 제거하지 않습니다.

### Docker를 사용할 수 없다면

화면에서 PC 조건과 대안을 안내합니다. WSL2가 허용되면 Ubuntu 내부에 Mattermost·PostgreSQL을 직접 설치하는 경로를 별도로 개발할 수 있습니다. WSL2 역시 가상화가 필요합니다. 가상화도 사용할 수 없다면 별도 Linux 서버 또는 기존 Mattermost 서버를 사용하는 구성이 대안이며, 이 경우 같은 Windows PC 한 대에서 서버까지 운영한다는 조건은 변경됩니다. 이 마법사는 아직 이러한 대안의 자동 설치·연결을 제공하지 않습니다. 조직 정책으로 Docker가 금지되면 승인된 환경을 사용하세요.

Docker 설치 파일은 동봉하지 않고 실제 동의·실행 시 다운로드합니다. 현재 고정 버전·공식 URL·체크섬은 `config/docker-desktop.json`에서 확인할 수 있습니다. 설치 파일과 서명 검증이 실패하면 실행하지 않습니다. 고정 파일이 더 이상 제공되지 않으면 임의의 다른 버전을 자동 실행하지 않고 공식 설치 안내를 확인하도록 중단합니다. [Docker 공식 설치·약관](https://docs.docker.com/desktop/setup/install/windows-install/), [공식 릴리스·체크섬](https://docs.docker.com/desktop/release-notes/)

## 2. Hermes·모델

`PC 확인·설치 계획`으로 경로와 고정 릴리스를 검토하고 동의 후 설치합니다. 이미 마법사로 설치한 Hermes가 있다면 `기존 Hermes·인증 확인`을 사용할 수 있습니다. 모델 계정 로그인은 인증 페이지에서 직접 진행하며, 계정에서 사용할 모델을 선택합니다. 실제 설치 무결성·로그인·모델은 연구팀 연결 전에 다시 확인합니다.

### 기존 Hermes를 그대로 연결하기 (0.9.0)

1. **이 PC의 기존 Hermes를 선택해 사용합니다**를 선택합니다. 이 선택은 표시된 로컬 설치의 코드를 실행하는 데 대한 명시적 동의입니다. 새 설치의 고정 commit·attestation 검증을 통과했다는 표시로 바꾸지는 않습니다.
2. 데이터 폴더는 기존 `HERMES_HOME`, 코드 폴더는 그 아래 `hermes-agent`인지 확인합니다. 환경 변수의 경로를 기본으로 표시하며 다르면 직접 수정합니다. 현재 지원 범위는 native Windows 소스 설치와 `venv\Scripts\python.exe`입니다. MSIX·WSL 내부 설치를 자동 인수하지 않습니다.
3. **기존 Hermes·인증 확인**을 누릅니다. 공식 저장소 origin, 안전한 로컬 경로·native 실행 파일 형식·소스 commit·런타임 API 호환성을 확인합니다. 인식 단계에서는 `hermes.exe --version`도 실행하지 않으며 화면 버전은 정적 소스 정보 또는 commit입니다. 기존 설치는 다른 commit이나 추가 런처가 있어도 지정 릴리스로 덮어쓰지 않습니다. 경로가 바뀌면 이전 확인 결과를 취소합니다.
4. 인증은 기존 홈에서 읽습니다. 인증 파일 복사·로그인·토큰 갱신·외부 모델 요청을 하지 않으며, 조회 중 파일 쓰기와 네트워크를 차단합니다. ‘저장된 인증 발견’은 실제 모델 호출로 계정 유효성까지 검증했다는 뜻이 아닙니다. 기존 모델 선택은 가능한 경우 그대로 표시합니다.
5. 기존 개인 Gateway를 시작·중지·재시작하거나 `--replace`로 교체하지 않습니다. 연구팀은 별도 권한·감사 중개 서비스를 사용합니다. 선택된 Hermes에 필요한 API가 없으면 자동 업그레이드하지 않고 실행을 보류합니다.
6. 연구팀은 새 `research-*` 프로필만 추가합니다. 같은 이름의 다른 기존 프로필은 거부합니다. 인증을 복제하지 않고 기존 root 인증 경로를 사용합니다. 설치 완료 후 실제 모델 응답은 운영 설정을 확정한 뒤 별도로 확인합니다.

이 모드에서는 **Hermes 설치**, **모델 계정 로그인**을 실행할 수 없습니다. 기존 인증이 없으면 원래 Hermes에서 계정 상태를 확인하세요. 설치 확인 단계는 읽기 전용이지만, 이후 실제 Hermes 실행 중 정상적인 OAuth 갱신은 원래 Hermes 인증 저장소에서 일어날 수 있습니다. 임의의 기존 프로필을 연구팀 소유로 인수하거나 인증 복제본을 만드는 기능은 없습니다.

기존 사용 모드를 선택하지 않은 새 설치 경로에는 이전과 같은 고정 릴리스·검증 기록 조건을 유지합니다. ZIP을 다른 폴더에 풀어도 기본 홈과 런타임은 공유하므로 격리 설치가 되지 않습니다. 기존 폴더·인증·프로필을 삭제하거나 검증을 끄지 마세요.

## 3. 네 에이전트 — 한 페이지에서 설정

이름·봇 토큰·역할을 네 행에서 입력합니다. 역할 기본값은 관리·조사·분석·감사입니다. 기존 profile ID와 폴더 이름은 유지합니다.

| 역할 | 원문 | 프로필 기본값 |
| --- | --- | --- |
| 관리 | assets/research-prompts/manager.txt | research-lead |
| 조사 | assets/research-prompts/researcher.txt | research-scout |
| 분석 | assets/research-prompts/analyst.txt | research-worker |
| 감사 | assets/research-prompts/auditor.txt | research-reviewer |

제공된 v0.1_20261015 TXT 전체를 공통 규칙 추가 없이 적용합니다. 역할을 바꿔 배정하면 지침도 해당 역할을 따라갑니다. ‘제공된 네 TXT 전체 불러오기’는 현재 편집 내용을 제공된 원문으로 되돌립니다. ‘역할 템플릿 저장’으로 수정한 내용은 연구팀 생성·재설정 때 반영됩니다.

### Mattermost 대화 기본값

- 모든 답변·배정·결과는 원래 요청의 스레드에 남깁니다. 스레드 안에서 요청해도 새 최상위 글로 분리하지 않습니다.
- 봇 간 응답은 실제 Mattermost 사용자 이름을 사용하는 명시적 `@멘션`으로만 연결합니다. 관리자가 허용된 작업자를 멘션해 배정하고, 작업자는 관리자를 멘션해 결과를 돌려줍니다. 표시 이름을 바꿔도 서버에서 확인한 사용자 이름을 사용합니다.
- 관리 에이전트만 같은 요청의 다른 봇 발언을 관찰합니다. 조사·분석·감사에는 자신에게 배정된 내용·허용된 자료·자신의 도구 결과만 전달합니다. 작업자 간 직접 호출은 열지 않습니다.
- 임의의 봇 글이나 위조 멘션만으로 작업을 실행하지 않습니다. 중개 실행기가 발급한 요청·작업·대상·스레드 기록과 역할 권한·감사·예산 검사를 모두 통과해야 합니다. 이 규칙은 `research/private.json`에 저장되어 재시작 후에도 유지됩니다.
- 여기서 ‘관리자만 본다’는 **관리 에이전트의 입력 범위**입니다. 사람 계정의 채널 열람 권한을 바꾸거나 다른 채널 구성원에게 봇 글을 숨기는 기능은 아닙니다. 기존 개인 Gateway의 Mattermost 설정도 변경하지 않습니다.

이 설정은 연구용 중개 실행기에서 강제합니다. Mattermost native 어댑터에 없는 봇 관찰 옵션을 임의로 추가하지 않습니다.

### 운영 설정과 보류

같은 페이지의 ‘운영 설정’에서 실제 값을 입력하고 저장합니다. 선택한 공통 모델은 네 역할의 초기 model/provider에 연결됩니다. 개별 역할 모델은 운영 설정에서 명시할 수 있습니다. null은 미정, []는 허용 없음이며, 빈 값을 무제한 또는 자동 허용으로 바꾸지 않습니다.

현재 마법사의 모델 연결은 기존 로그인인 openai-codex와 공식 Codex endpoint 범위입니다. 임의 provider·사용자 지정 모델 서버를 자동 지원한다고 간주하지 않습니다. 기관 내부 모델 전용 자료는 승인된 내부 모델 어댑터가 별도로 연결될 때까지 보류해야 합니다.

- human.allowed_user_ids: 실제 연구자 Mattermost 사용자 ID. 봇과 미등록 사용자는 연구 요청·승인을 할 수 없습니다.
- allow_model_egress: 해당 역할 자료를 선택한 외부 모델에 보내도 되는지 명시합니다. 기관 내부 전용 자료는 외부 모델 사용 동의로 대체하지 마세요.
- tools: 구현된 중개 도구만 선택합니다. read_text, write_artifact, dispatch, audit, complete 외 도구는 거부됩니다. dispatch는 관리자만, audit는 감사자만, 완료 판정은 관리자만 가능합니다.
- read_roots: 승인된 입력 자료 폴더의 절대 경로. 설치·인증·정책·토큰·출력 저장소와 겹치는 경로는 허용하지 않습니다.
- write_roots: 역할별 불변 산출물 저장소인 RuntimeRoot\\research\\policy.artifacts\\역할명 경로만 허용됩니다. 감사자는 다른 역할 원본을 작성·교체할 수 없습니다.
- call_targets: 관리자가 호출할 researcher, analyst, auditor 중 승인한 대상. 다른 역할은 []로 지정해야 합니다.
- external_domains: 현재 중개 실행기는 외부 검색·일반 네트워크 도구를 제공하지 않습니다. 목록을 넣어도 네트워크 권한이 생기지 않습니다.
- limits: 역할별 attempts, revisions, audits, seconds, tokens, max_output_tokens, per_call_timeout_seconds를 모두 명시합니다. 0은 실행 허용량 없음입니다. 오프라인 준비·파일 읽기도 각각 시도 1회와 실행 시간을 소비하며, 모델 호출은 별도로 차감합니다. 각 자식 작업에 같은 per_call_timeout_seconds를 적용합니다. 실제 사용량을 알 수 없으면 예약한 상한을 소비한 것으로 처리하며 측정값으로 꾸미지 않습니다.

모델·도구·자료·한도·API 호환성이 미정/미지원이면 해당 실행을 보류합니다. 설치 파일 저장과 연구 실행 준비 완료는 별개로 표시됩니다. 임의 코드 실행·수치 재계산·검색·내부 웹 게시 도구는 아직 제공하지 않습니다. 특히 S2 최종 숫자 검증기는 미연결 상태이므로 코드에서도 pass 기록을 거부합니다. 그런 기능이 필요한 감사는 확인 불가 또는 보완 대기이며 자동 통과하지 않습니다.

### 실행과 재시작

연구 채널에서 허용된 연구자가 다음 명령을 보냅니다. 실제 모델 호출은 설정 검증을 통과한 뒤에만 발생하며 과금/계정 사용량이 생길 수 있습니다.

```text
/research {"scenario":"S1","scope":"확정한 연구 범위","input_refs":[],"outputs":["직접 지정한 산출물"]}
/research-status 요청ID
/research-confirm 요청ID 산출물ID 버전 SHA256 확인종류
/research-resume 요청ID
```

S1/S2/S3와 실제 범위·입력 자료 참조·필요 산출물을 지정합니다. 위 문자열은 형식 예시이며 자동 적용 값이 아닙니다. 필수 정보 없는 간단 요청은 모델을 호출하지 않고 보완 안내만 반환합니다. 관리자가 작업을 배정하고, 조사·분석 담당자는 새 버전만 작성하며, 감사자는 배정된 정확한 원본을 읽고 새 감사 기록만 남깁니다. 분석 본 작업은 조사 결과의 중간 감사 통과를 요구합니다. 수정 시 이전 통과는 새 버전에 재사용되지 않고, 종속 결과도 다시 확인합니다.

확인종류는 human_approval, researcher_confirmation, access_verified, exact_version_shared, publication_access_verified입니다. 상태 명령이 보여준 정확한 ID·버전·SHA256에만 기록됩니다. 에이전트가 연구자 승인을 만들 수 없습니다. S3 외부/내부 게시는 자동 구현되지 않았으므로 게시·접근 확인이 없으면 완료할 수 없습니다.

중개 서비스 하나를 Windows 로그인 자동 실행으로 등록합니다. 네 TXT는 프로필 SOUL.md와 RuntimeRoot\\research\\prompts에 유지되며, 실제 모델 호출 때 전체 지침 해시를 검증하고 시스템 메시지로 1회 불러옵니다. 요청·작업·산출물·감사·예산 예약은 SQLite에 남습니다. 재시작은 모델 작업을 자동 재실행하지 않습니다. 보류된 요청은 명시적 resume으로만 이어가며, 실행 중 중단된 요청은 상태를 확인해야 합니다.

### 기존 환경 보존과 보안

개인 Hermes 설치·인증·기존 개인 프로필·기존 Gateway는 자동 변경·중지하지 않습니다. 이 마법사의 이전 네 native Gateway 팀은 새 서비스와 동시 실행하지 않으며 자동 전환하지 않습니다. 이미 설치한 이전 연구팀을 전환하려면 별도의 명시적 마이그레이션이 필요합니다.

봇 토큰은 연구 서비스의 private.json에만 저장하고 디렉터리 ACL을 현재 Windows 사용자와 SYSTEM으로 제한합니다. 연구 프로필 .env에는 Mattermost 토큰을 두지 않아 기존 multiplexer가 권한 검사를 우회해 봇을 실행하지 못하게 합니다. 운영 정책을 바꾼 경우 기존 요청은 새 정책으로 자동 승계되지 않습니다.

같은 Windows 사용자나 관리자의 악의적인 파일 수정까지 차단하는 OS 샌드박스는 아닙니다. 일반 Hermes CLI를 수동 실행한 것은 이 중개 서비스의 연구 실행이 아닙니다. private.json, SQLite, 산출물, 인증·토큰·전체 로그를 Git/진단 ZIP/공개 이슈에 올리지 마세요.

자동 테스트는 가짜 모델·Mattermost·임시 프로필로 권한과 감사 게이트를 확인합니다. 실제 네 모델의 유료 응답과 사용자 선택 정책에 대한 종단간 승인은 별도입니다. 로컬 수정이 GitHub 게시나 기존 실행 중 팀의 업데이트를 뜻하지 않습니다.
